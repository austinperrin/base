# Repository Roadmap

[Docs](../README.md) > Roadmap

The roadmap organizes work into milestones with defined outcomes. Phases describe
the dependency order within a milestone. Each milestone has its own document so
its scope, progress, and completion evidence stay together.

## Milestone Index

| Milestone | Purpose | Status |
| :--- | :--- | :--- |
| [Milestone 0: Repository Scaffolding](milestone-0-repository-scaffolding.md) | Establish initial repository practices | Completed |

Milestone 0 records the completed repository scaffolding and its verification.
Milestone 1 onward tracks project work after that initial setup.

## Continuing with Milestone 1

Preserve Milestone 0 as the record of the repository's initial scaffolding. Create
`milestone-1-your-project-goal.md` for the next project milestone and add it to the
index above. Define its goal and phases according to the work your project needs.

Include the milestone's owner, status, scope, dependencies, phases, completion
criteria, and links to relevant standards and decisions. Record evidence as work
is completed. Follow the same approach for subsequent milestones.

Milestone 0's completion does not resolve Proposed decisions or replace the
project-specific settings and checks required when starting a new repository.

## Organization and Maintenance

Keep each milestone's detailed plan in its own file, with the index providing a
short summary and status. Use phase sections within the milestone initially;
when a phase needs a separate document, link it from the milestone and register
it in this index as well.

Update the milestone and index together when scope or status changes. Keep detailed
requirements in their canonical standards and link to them from the roadmap.
Follow the [documentation standard](../standards/documentation.md) for formatting
and navigation.
