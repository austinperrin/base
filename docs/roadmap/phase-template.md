# Phase Planning Template

[Docs](../README.md) > [Roadmap](README.md) > Phase Planning Template

Copy this page to `milestone-N-short-name/phase-N-short-name.md`. Replace the
title, breadcrumb, prompts, and relative links for the new location. Link the
phase from its milestone `README.md` and the
[roadmap schedule](README.md#schedule). Keep owner, estimate, dates, variance,
and status in the schedule so progress has one source of truth.

## Goal and Prerequisites

**Goal:** State the observable result this phase must deliver.

**Prerequisites:** Link earlier phases, decisions, and other work required to
start. Identify any unresolved dependency and its owner.

## Development Checklist

Keep work items small enough for focused pull requests. Link an issue or pull
request when one exists; define the result before choosing a branch name.

- [ ] Describe the first reviewable change.
- [ ] Add the remaining changes required for the phase goal.

## Review Checklist

- [ ] Run applicable checks and review the results.
- [ ] Confirm documentation and decisions match the delivered work.
- [ ] Review the phase outcome against its goal and prerequisites.

## Exit Criteria

- [ ] Describe the observable result required to complete this phase.
- [ ] Link evidence that the result was reviewed and delivered.

## Progress and Evidence

Record the latest review date, current blocker or delivery risk, and next action.
Link reviewed pull requests, check runs, decisions, or other evidence. Explain
scope changes here. Record the reason for a schedule change on the milestone
page; update its date and status values in the roadmap schedule.
